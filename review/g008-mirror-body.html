G008 거울 인간! 다 함께 몸으로 표현해요 — C# 이식 확인

HTML 게임 「거울 인간」(G008 v2.0 카메라판, 회원님이 주신 HTML 파일)을 이 저장소의 C# 틀(판정 → 감독 → 무대)로 옮겼습니다. 화면 속 시범 자세를 보고 온몸으로 똑같이 만들어 잠깐 버티는 게임입니다. 표현 카드 열 가지와 비교 셈은 원본 숫자 그대로이고, 인원만 앱 카메라 상한에 맞춰 1~6명으로 했습니다. 주개발자 게임과 같은 흐름(참가 → 동작 연습 → 시작)을 넣었고, 앱 「웹 게임」에 붙여 넣는 HTML 판(줄인 판)도 함께 올렸습니다. 새 파일만 더했고 기존 파일은 고치지 않았습니다.

흐름 — 참가 → 동작 연습 → 시작

단계누가무엇
1. 참가 화면앱(그대로)카메라 앞에서 참가 자세 → 모두 준비 자세 → 안내 단계로
2. 입장 뒤 동작 연습이 게임(MirrorBodyPractice)전신 보이기(머리부터 발끝까지 1.5초 — 원본 준비 확인) → 「반짝반짝 별」(원본 준비 화면의 시범 자세, 경기와 같은 성공 규칙 72점 1.5초) → 시작 자세. 단계마다 참가자 전원이 통과해야 다음으로, 모두 통과하면 「잘했어요!」 0.8초. 어느 단계든 한 명이 두 팔을 ㄴ자로 올리고 0.25초 버티면 바로 시작. 선생님은 앱의 「바로 시작」/Enter.
3. 게임 시작앱 3초 세기 → 이 게임시범 보기 3초 → 따라 하기 9초 → 결과 3초를 표현 수만큼. 다 하면 앱이 경기를 닫고 결과 화면

「씩씩한 선인장」은 시작 자세(두 팔 ㄴ자)와 모양이 같아 연습에 쓰지 않았습니다. 별은 팔을 곧게 뻗어 시작 자세로 읽히지 않습니다(검사로 확인).

직접 해 보기

C# 판정과 같은 규칙과 숫자로 움직입니다. 카메라 대신 원본의 「가상 체험」처럼 가상 참여자가 시범을 따라 합니다(마지막 사람은 세 번째 표현마다 일부러 따라 하지 않아 실패와 연속 끊김을 볼 수 있습니다). 「1번 참가자 = 키보드」로 두면 1~0 키로 표현 카드 1~10번 자세를(누르고 있는 동안), Q로 시작 자세를 냅니다. 아무 키도 안 누르면 팔 내리고 선 자세입니다. Enter는 선생님의 「바로 시작」.

G008 · 6학년 체육 · 표현 활동

거울 인간! 다 함께 몸으로 표현해요

화면 속 표현을 보고 → 온몸으로 똑같이 만들고 → 잠깐 멈춰 균형을 유지해요. 카메라가 팔·다리 방향을 시범과 비교해 일치도를 알려 줍니다.

진행 방법
  1. 카메라에 머리부터 발끝까지 보이게 서고, 옆 사람과 겹치지 않게 간격을 둡니다.
  2. 시범을 3초 관찰한 뒤, 정해진 시간 동안 같은 자세를 만들어요.
  3. 일치도가 기준을 넘은 채로 정해진 시간을 버티면 성공! 연속 성공은 보너스.
  4. 몸이 잘 안 보이면 「평가 보류」 — 점수 없이 넘어갑니다.

HTML 판 — 줄인 판으로 함께 올렸습니다

주개발자 요청(「HTML·유니티 둘 다 올려 보라」)대로, 앱의 「AI로 게임 만들기 → HTML 붙여넣기」에 그대로 넣으면 도는 HTML 한 파일도 같은 PR에 넣었습니다: docs/progress/g008-mirror-body-web/game.html(설명 README).

그런데 이 게임은 HTML 판을 원본 그대로 만들 수 없습니다. 앱이 붙여 넣은 웹 게임에 넘겨 주는 카메라 입력은 동작 이름(Raise 두 팔 들기 · Squat 앉기 · Jump 점프 등)과 손 하나의 위치뿐이고, 어깨·팔꿈치·손목·무릎 같은 관절 골격은 넘기지 않습니다(저장소 WebPlayerBridge.PromptContract, 11-17 main 확인). 거울 인간은 팔다리 열두 관절의 각도를 시범과 비교하는 게임이라, 지금 통로로는 그 판정을 할 수 없습니다. 회원님 결정(11-17 「줄인 HTML 판도 만든다」)으로 넘어오는 동작만으로 가를 수 있는 판을 만들었습니다.

파일무엇

검증한 것과 안 한 것

  • Unity 맥 Unity 6000.5.9f1, 빌드 대상 Win64(학교 PC와 같은 조건)로 가지를 받아 컴파일 오류 0, G008 EditMode 검사 57건 모두 통과(골라 돌림 — 전체 검사는 아님).
  • .NET 같은 57건을 .NET 8·C# 9·경고를 오류로·NUnit 3.14로도 돌렸습니다(main의 실제 파일과 함께 묶음).
  • 끝까지 감독 검사는 골격 좌표만 넣어 연습 → 시작 자세 → 표현 5개를 돌리고, 흘린 Touch·Press가 판이 센 점수와 같은지 봅니다.
  • 빨간불 확인 판정·연습·감독 규칙 46개를 하나씩 끄면 모두 검사가 실패합니다. 처음엔 11개가 구멍이라 검사 10건을 더했고, 하는 일이 없던 중복 코드 하나는 지웠습니다. 검사가 잡은 결함도 하나 있었습니다 — 「나무」 손목이 인형 틀 위로 잘릴 뻔했습니다.
  • HTML 판 앱 웹 게임 검사기 통과(위 절).
  • 안 함 앱 화면 촬영(앱에 아직 연결 전이라 앱 화면이 없음), 실물 카메라로 한 판(만든 분들이 확인 — PR #100에서 주개발자께 문의 중), Windows 실행.

실물에서 봐 주셨으면 하는 것

  • 좌우 — 학생이 왼팔을 들면 인형도 화면 왼쪽 팔을 드는지, 「왼쪽으로 반짝」·「왼발로 선 홍학」이 맞게 판정되는지. 앱 골격의 가로가 거울 화면 좌표라는 전제로 짰습니다.
